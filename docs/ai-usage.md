# AI 工具使用说明

## 1. 使用的 AI 工具

本项目开发过程中参考和使用了以下 AI 工具：

| AI 工具 | 使用场景 |
| --- | --- |
| ChatGPT | 需求分析辅助、接口设计建议、论文初稿生成、README 文档生成 |
| Cursor | 代码补全、局部重构、Bug 排查 |
| GitHub Copilot | 前端组件代码补全、Java Service 层样板代码补全 |
| Trae 或 CodeBuddy | 项目结构检查、页面样式辅助、SQL 优化建议 |

## 2. 使用场景

### 2.1 需求分析辅助

使用 AI 帮助梳理高校软件生产实习项目需要体现的完整流程，包括需求分析、系统设计、数据库设计、编码、测试、部署和版本管理。

### 2.2 数据库表设计辅助

使用 AI 协助整理用户、笔记、分类、标签、收藏、评论、公告、AI 记录、日志等数据表字段，并补充字段注释和关系说明。

### 2.3 后端接口代码生成

使用 AI 辅助生成 Controller、DTO、VO、Service、Mapper 和统一返回结果等基础代码，再由开发者进行人工整合、调试和安全校验。

### 2.4 前端页面代码生成

使用 AI 辅助生成 Vue3 页面骨架、Element Plus 表格表单、路由配置、Pinia 状态管理和 Axios 封装。

### 2.5 Bug 修复

在出现接口参数不一致、权限判断不完整、状态流转遗漏等问题时，使用 AI 提供排查方向，再结合实际运行结果进行修正。

### 2.6 SQL 优化

使用 AI 检查 SQL 表结构是否覆盖业务需求，并对索引、外键、字段注释和初始化数据提出建议。

### 2.7 文档和论文生成

使用 AI 辅助生成 README、API 文档、部署文档、测试用例、AI 使用说明和结课论文初稿。

## 3. AI 生成内容占比估算

| 内容类型 | AI 辅助占比 | 人工工作 |
| --- | --- | --- |
| 需求与设计文档 | 约 60% | 需求取舍、课程要求匹配、内容审核 |
| 后端基础代码 | 约 45% | 接口联调、权限校验、业务流程修正 |
| 前端页面代码 | 约 50% | 页面交互、样式调整、路由联调 |
| SQL 脚本 | 约 40% | 字段确认、外键校验、测试数据调整 |
| 论文和答辩材料 | 约 60% | 表述润色、截图替换、结合个人开发过程修改 |

综合估算 AI 生成或辅助内容约占 50%，核心需求理解、代码整合、环境部署、调试测试和最终验收由本人完成。

## 4. AI 工具优点

- 能快速生成项目结构和样板代码，提高开发效率。
- 能帮助补全边界场景，例如权限控制、异常处理和状态流转。
- 能辅助撰写规范化文档，减少重复性文字工作。
- 能提供多种技术方案，便于比较和选型。

## 5. AI 工具不足

- AI 生成代码可能存在版本不匹配、依赖错误或细节遗漏。
- 对具体运行环境不了解，需要人工配置数据库、端口和依赖。
- 对复杂业务规则容易生成表面可用但边界不足的代码。
- 文档内容需要结合本人实际开发过程修改，不能直接照搬。

## 6. 人机协作反思

AI 在本项目中主要承担“辅助工程师”的角色，适合完成需求梳理、样板代码生成、文档初稿和问题排查。但项目能否真正运行，仍取决于开发者对业务流程、权限边界、数据库关系和接口联调的理解。通过本项目实践可以认识到，AI 可以显著提升软件生产效率，但不能替代软件工程中的分析、设计、测试和质量负责。

## 7. 系统真实 AI 配置说明

项目后端的 AI 问答助手支持真实大模型调用，采用 OpenAI-compatible `/chat/completions` 接口格式。可接入 DeepSeek、OpenAI、阿里云百炼、智谱 AI 或本地大模型网关。

推荐配置方式：登录管理员账号 `admin / 123456`，进入“后台管理 - AI 配置”，选择供应商模板，填写接口地址、模型名称和 API Key 后保存。系统查询配置时只显示脱敏 Key，避免在页面和接口中暴露明文。

如果不方便在页面中配置，也可以在数据库首次初始化默认配置时通过环境变量预置：

推荐 DeepSeek 配置：

```powershell
$env:AINOTE_AI_MODE="real"
$env:AINOTE_AI_API_BASE_URL="https://api.deepseek.com/v1"
$env:AINOTE_AI_API_KEY="你的DeepSeek API Key"
$env:AINOTE_AI_MODEL_NAME="deepseek-chat"
```

推荐 OpenAI 配置：

```powershell
$env:AINOTE_AI_MODE="real"
$env:AINOTE_AI_API_BASE_URL="https://api.openai.com/v1"
$env:AINOTE_AI_API_KEY="你的OpenAI API Key"
$env:AINOTE_AI_MODEL_NAME="gpt-4o-mini"
```

系统不会把 API Key 写入代码仓库。AI 问答页面会显示本次回答使用的模型名称，例如 `deepseek-chat`、`gpt-4o-mini` 或 `mock-ai`。如果显示 `mock-ai`，说明当前没有配置真实 API Key，或真实调用失败后触发了失败降级。
