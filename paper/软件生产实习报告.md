# 智学 AI 学习笔记系统的设计与实现

## 摘要

智学 AI 学习笔记系统是一个面向大学生和学习者的前后端分离 Web 应用，旨在解决学习笔记分散、知识点整理效率低、复习重点不清晰和缺少智能辅助的问题。系统采用 Spring Boot 3、Spring Security、JWT、MyBatis Plus、MySQL 8、Vue3、Vite、TypeScript、Element Plus 和 ECharts 等技术实现，支持用户注册登录、学习笔记管理、分类标签管理、收藏评论、AI 摘要、AI 标签推荐、AI 问答、学习统计和管理员后台管理。项目按照软件生产实习要求完成了需求分析、概要设计、数据库设计、系统实现、测试、部署和 GitHub 版本管理，并形成完整文档。系统通过模拟 AI 模式保证无 API Key 情况下也能演示，同时保留 OpenAI 兼容真实 API 接入能力，具有较好的扩展性和课程展示价值。

关键词：学习笔记；前后端分离；Spring Boot；Vue3；JWT；AI 摘要；软件工程

## 1 需求分析

### 1.1 项目背景

在高校课程学习和软件实训过程中，学生通常需要记录大量课程知识、代码片段、实验过程和复习要点。传统笔记工具虽然可以完成文字记录，但在知识整理、重点提取、标签归类和复习建议方面支持不足。随着大模型技术的发展，AI 可以辅助完成摘要生成、重点提取、标签推荐和问答解释。基于此，本项目设计并实现“智学 AI 学习笔记系统”，通过前后端分离架构将笔记管理与 AI 学习辅助结合起来，提高学习资料整理和复习效率。

### 1.2 可行性分析

技术可行性方面，Spring Boot、Vue3、MySQL、JWT 和 MyBatis Plus 均为成熟技术，适合开发课程实训项目。AI 模块采用可替换式设计，默认使用 mock 模式，后续可接入 OpenAI、DeepSeek、阿里云百炼、智谱 AI 或本地大模型。经济可行性方面，项目主要依赖开源框架，无需额外商业授权。操作可行性方面，系统页面采用 Element Plus 组件库，包含左侧菜单、表格分页、表单校验、弹窗提示和图表展示，用户学习成本较低。

### 1.3 用户角色分析

系统包含普通用户和管理员两个角色。普通用户可以注册登录、创建学习笔记、编辑自己的笔记、提交 AI 处理、查看 AI 摘要、发布和归档笔记、收藏公开笔记、评论已发布笔记、查看学习统计并使用 AI 问答助手。管理员可以查看所有用户、禁用和启用用户、重置密码、管理所有笔记、删除违规笔记、管理分类标签、发布公告、审核评论和查看系统统计。

### 1.4 功能需求分析

系统功能主要包括用户模块、笔记模块、分类模块、标签模块、AI 智能模块、收藏模块、评论模块、公告模块、学习统计模块和管理员模块。用户模块负责注册、登录、JWT 认证和个人资料维护。笔记模块负责笔记生命周期管理。AI 模块负责摘要、标签推荐、学习重点、考试重点、学习建议和问答。管理员模块负责系统基础数据和内容审核。

### 1.5 非功能需求分析

系统需要具备安全性、可维护性、可扩展性和易用性。安全性体现在 JWT 认证、RBAC 权限控制和普通用户数据隔离。可维护性体现在后端 Controller、Service、Mapper、Entity、DTO、VO 分层结构和前端组件化开发。可扩展性体现在 AI 模块的 mock/real 双模式设计。易用性体现在简洁现代的页面布局、清晰的菜单导航和可视化学习统计。

### 1.6 用例图说明

普通用户用例包括注册、登录、创建笔记、编辑笔记、提交 AI 处理、发布笔记、收藏笔记、评论笔记、查看统计和使用 AI 问答。管理员用例包括用户管理、笔记管理、分类管理、标签管理、公告管理、评论管理和系统统计。用例关系体现了普通用户与管理员在权限范围上的差异。

## 2 概要设计

### 2.1 系统总体架构

系统采用前后端分离架构。前端通过 Vue3 构建单页应用，使用 Axios 调用后端 RESTful API。后端基于 Spring Boot 提供接口服务，使用 Spring Security 和 JWT 实现认证授权，使用 MyBatis Plus 访问 MySQL 数据库。AI 模块位于后端 Service 层，通过统一接口屏蔽 mock 模式和真实 API 模式差异。

### 2.2 技术架构设计

前端技术架构包括 Vue3、Vite、TypeScript、Vue Router、Pinia、Axios、Element Plus、ECharts 和 md-editor-v3。后端技术架构包括 Spring Boot 3、JDK 17、Spring Security、JWT、MyBatis Plus、MySQL 8、Lombok、Maven 和 Knife4j。数据库使用 MySQL 8，所有表包含 id、create_time、update_time 和 is_deleted 字段。

### 2.3 功能模块设计

系统模块划分如下：用户认证模块、学习笔记模块、分类标签模块、AI 智能模块、收藏评论模块、公告模块、统计模块和后台管理模块。各模块通过 RESTful API 对前端提供服务，前端按照页面和业务划分视图组件。

### 2.4 业务流程设计

学习笔记生命周期从用户创建笔记开始，状态为 DRAFT。用户可以保存草稿并编辑内容，随后提交 AI 处理，状态变为 WAITING_AI。AI 处理完成后生成摘要和建议，状态变为 AI_FINISHED。用户确认后发布笔记，状态变为 PUBLISHED。公开笔记可以被其他用户查看、收藏和评论。用户可以将已发布笔记归档，状态变为 ARCHIVED，最终可删除为 DELETED。

### 2.5 权限设计

系统采用 RBAC 思路，用户表中保存 role 字段区分 USER 和 ADMIN。普通用户只能管理自己的草稿、AI 处理中和归档笔记，可以查看他人已发布笔记，但不能修改他人笔记。管理员可以查看和管理所有用户、笔记、分类、标签、公告和评论。后端通过 Spring Security 配置 `/api/admin/**` 仅管理员可访问，并在业务层补充数据归属校验。

## 3 数据库设计

### 3.1 数据库概念设计

数据库围绕用户、笔记和 AI 使用记录展开。用户是笔记、收藏、评论和 AI 记录的主体。笔记属于一个分类，可以绑定多个标签。收藏和评论体现用户与公开笔记之间的互动。AI 使用日志记录 AI 功能调用情况，用于学习统计。

### 3.2 ER 图说明

ER 关系包括：用户与笔记是一对多关系；分类与笔记是一对多关系；笔记与标签通过 note_tag 建立多对多关系；用户与笔记通过 favorite 建立收藏关系；笔记与评论是一对多关系；用户与 AI 聊天记录、AI 使用日志是一对多关系。

### 3.3 数据表设计

系统创建 sys_user、sys_role、sys_user_role、note、category、tag、note_tag、favorite、comment、announcement、ai_chat_record、ai_usage_log、operation_log、login_log 共 14 张表。sys_user 表保存用户账号、加密密码、昵称、邮箱、头像、状态和角色。note 表保存笔记标题、正文、AI 结果、状态和统计字段。ai_chat_record 表保存用户问题、AI 回答和模型名称。ai_usage_log 表保存 AI 类型、输入输出 token 估算和调用状态。

### 3.4 表关系说明

note.user_id 关联 sys_user.id，note.category_id 关联 category.id。note_tag.note_id 关联 note.id，note_tag.tag_id 关联 tag.id。favorite.user_id 关联 sys_user.id，favorite.note_id 关联 note.id。comment.note_id 关联 note.id，comment.user_id 关联 sys_user.id。ai_chat_record.user_id 和 ai_usage_log.user_id 均关联 sys_user.id。

## 4 系统实现

### 4.1 用户登录注册模块实现

用户注册时，后端校验用户名是否重复，并使用 BCrypt 对密码加密保存。用户登录时，后端校验账号密码和用户状态，登录成功后生成 JWT token。前端通过 Pinia 保存用户信息，通过 LocalStorage 保存 token，并在 Axios 请求拦截器中自动添加 Authorization 请求头。

### 4.2 笔记管理模块实现

笔记模块使用 NoteController 提供创建、编辑、删除、分页、详情、提交 AI、发布和归档接口。NoteService 负责状态流转和权限判断。系统规定 DRAFT 和 AI_FINISHED 可以编辑，WAITING_AI 不允许编辑，PUBLISHED 可以收藏评论和归档，ARCHIVED 不允许编辑和评论。

### 4.3 AI 摘要模块实现

AI 摘要接口接收笔记标题和正文，返回摘要、学习重点、考试重点和学习建议。系统默认使用 mock 模式，能够根据笔记内容生成演示结果。若配置真实 API Key，则通过 OpenAI 兼容接口调用大模型。

### 4.4 AI 标签推荐模块实现

AI 标签推荐接口根据标题和正文生成标签列表。mock 模式下根据关键词匹配 Java、Vue、MySQL、AI 等标签，真实模式下由大模型返回逗号分隔的标签列表，后端进行解析并返回数组。

### 4.5 AI 问答模块实现

AI 问答助手提供学习问题回答功能，前端以聊天形式展示用户问题和 AI 回答。后端保存问题、回答和模型名称到 ai_chat_record 表，并记录 AI 使用日志。

### 4.6 管理员后台模块实现

管理员后台包括用户管理、笔记管理、分类管理、标签管理、公告管理和评论审核。前端根据用户角色动态显示后台菜单，后端通过 Spring Security 限制 `/api/admin/**` 仅 ADMIN 角色访问。

### 4.7 学习统计模块实现

学习统计模块统计笔记总数、本周新增、收藏数量、AI 使用次数、分类分布和月度学习趋势。前端使用 ECharts 展示折线图、柱状图和饼图，适合课程答辩演示。

## 6 项目部署

### 6.1 数据库部署

使用 MySQL 8 创建 `ai_study_note` 数据库，并导入 `database/schema.sql` 和 `database/data.sql`。初始化数据包含管理员账号、普通用户账号、测试分类、测试标签、测试笔记和测试公告。

### 6.2 后端部署

进入 backend 目录，修改 application.yml 中数据库连接信息，执行 `mvn clean package -DskipTests` 打包，然后使用 `java -jar target/ai-study-note-backend.jar` 启动服务。

### 6.3 前端部署

进入 frontend 目录，执行 `npm install` 安装依赖，执行 `npm run build` 生成 dist 目录。开发环境可使用 `npm run dev` 启动，生产环境可将 dist 部署到 Nginx。

### 6.4 GitHub 版本管理

项目采用 main、dev 和 feature 分支模型。main 保存稳定版本，dev 保存开发版本，feature 分支用于不同模块开发。提交信息使用 init、feat、fix、docs、test、chore 等规范，最终创建 v1.0.0 标签作为结课提交版本。

### 6.5 项目运行说明

运行顺序为：启动 MySQL 并导入数据，启动后端 Spring Boot 服务，启动前端 Vue3 服务，使用测试账号登录系统。管理员账号为 admin/123456，普通用户账号为 user/123456。

## 7 AI 工具使用说明

### 7.1 使用的 AI 工具

项目开发过程中使用 ChatGPT、Cursor、GitHub Copilot、Trae 或 CodeBuddy 进行需求分析辅助、代码生成辅助、Bug 排查和文档生成。

### 7.2 AI 辅助开发场景

AI 主要用于需求分析、数据库设计、后端接口代码生成、前端页面代码生成、SQL 优化、README 文档生成和论文初稿生成。

### 7.3 AI 生成内容占比

综合估算 AI 辅助内容约占 50%。其中需求文档和论文初稿 AI 辅助占比较高，核心代码整合、调试、测试和最终验收由本人完成。

### 7.4 AI 代码质量评价

AI 能快速生成样板代码和文档结构，但可能出现依赖版本不匹配、业务边界遗漏和表述不符合实际开发过程的问题。因此 AI 输出必须经过人工修改、运行验证和测试。

### 7.5 人机协作反思

AI 是提高软件生产效率的辅助工具，但不能替代开发者对业务需求、系统架构、数据库关系和代码质量的负责。通过本项目实践，我认识到合理使用 AI 可以缩短重复性工作时间，使开发者将更多精力投入业务理解、系统集成和测试验证。

## 8 总结与反思

### 8.1 项目完成情况

本项目完成了前后端分离的 AI 学习笔记系统，包含用户认证、笔记生命周期、AI 摘要、AI 标签推荐、AI 问答、收藏评论、学习统计和管理员后台管理功能。

### 8.2 遇到的问题

开发过程中遇到的问题包括 JWT 权限控制配置、普通用户数据隔离、笔记状态流转、AI mock 与真实 API 的兼容、前端路由守卫和统计图表渲染等。

### 8.3 解决方法

通过分层设计、统一异常处理、业务层权限校验、枚举管理状态、Axios 拦截器和 ECharts 组件化封装等方式解决上述问题。

### 8.4 学习收获

通过本项目，我系统实践了 Spring Boot 后端开发、Vue3 前端开发、MySQL 数据库设计、RESTful API 设计、JWT 权限控制、GitHub 版本管理和 AI 工具辅助开发。

### 8.5 后续改进方向

后续可增加文件上传、笔记全文检索、错题本、学习计划、消息通知、在线协同编辑、真实大模型多供应商切换和自动化测试，提高系统实用性和工程质量。
